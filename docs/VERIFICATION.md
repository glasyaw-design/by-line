# 검증 결과

비교 대상은 네 가지입니다.

- **원본:** `original/바이라인_1.6_전체소스.html`을 기존 Vercel 배포와 같은 문서 골격으로 감싼 것
- **분리본:** `npm run dev`로 연 프로젝트 폴더
- **`dist`:** `npm run build` 결과를 `npm run preview`로 연 것
- **단일:** `dist-single/`

브라우저는 Playwright의 Chromium(헤드리스)을 썼고, 모두 로컬 서버(`scripts/serve.mjs`)로 열었습니다.
무작위 게임이므로 **테스트에서만** `Math.random`과 `Date`를 고정했습니다. 원본을 같은 조건으로 두 번 돌려 결과가 완전히 같은 것을 먼저 확인한 뒤 비교했습니다. 제품 코드에는 테스트용 장치를 넣지 않았습니다.

## 5. `file://` (서버 없이 더블클릭)

- 분리본·단일·원본 모두 게임이 돌아가고 상태도 같습니다.
- 음악은 세 판 모두 브라우저 보안(CORS)으로 막혀 합성 음악으로 대체됩니다. 원본도 같은 기존 동작입니다.
- 분리본은 그림이 별도 파일이라, `file://`에서는 「커리어 1면 이미지 저장」(캔버스 → PNG)이 브라우저 보안에 막힐 수 있습니다. 원본·단일은 그림이 내장돼 있어 괜찮습니다. **서버로 열면 같습니다.** 이 경우는 화면 캡처로 확인하지 않았습니다.

## 확인하지 못한 것

- **Vite**: 이 작업 환경은 npm 저장소 접속이 막혀 설치할 수 없었습니다. 그래서 Vite 대신 외부 패키지가 필요 없는 Node 스크립트로 `dev`·`build`·`preview`를 만들었고, 이 명령들은 모두 실제로 실행해 확인했습니다.
- **Vercel 실제 배포**: `vercel.json`에 `buildCommand`·`outputDirectory`를 추가했지만 실제 Vercel에 올려 보지는 못했습니다. `api/presence.js`(접속자 카운터)도 실행해 보지 못했습니다. 코드는 기존 그대로입니다.
- **다른 브라우저·실기기**: Chromium 헤드리스만 썼습니다. iOS Safari, 안드로이드, Firefox는 확인하지 않았습니다.
- **소리**: 음악 파일 요청·응답까지만 확인했고, 실제로 들리는지는 확인하지 않았습니다.
- **장기 플레이**: 비교는 최대 26개월(18개월 + 이어서 8개월)까지입니다. 10년짜리 장기 플레이는 원본에서만 따로 돌렸고 분리본으로는 다시 돌리지 않았습니다.
- **내보내기 파일 다운로드 버튼**(`.txt` 저장): 코드 문자열 내보내기·가져오기만 확인했습니다.
- **구글 폰트**: 외부 인터넷이 막혀 확인하지 못했습니다. 경로는 원본과 같습니다.

## 따로 알려 드릴 점 (고치지 않음)

1. `bribeEvent`·`bribeOut`이 바탕 코드와 1.6 봉투 개편(`v43.js`)에 두 번 선언돼 있습니다. 쓰이는 건 v43 판이고, 옛 판은 실행되지 않는 코드입니다. 이번 작업 범위가 아니라 남겨 두었습니다.
2. 음악 경로를 `assets/audio/`로 옮겼으므로, 예전 배포에 `index.html` 파일 하나만 바꿔 넣는 방식이라면 `bgm/` 폴더 대신 `assets/audio/` 폴더도 같이 올려야 합니다.
3. 그림이 파일로 나뉘어, 처음 접속할 때 그림이 내장돼 있던 원본보다 조금 늦게 뜰 수 있습니다. 로컬 서버에서는 차이를 확인하지 못했습니다.
