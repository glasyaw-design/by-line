# 검증 결과

비교 대상은 네 가지입니다.

- **원본:** `original/바이라인_전체소스.html`을 기존 Vercel 배포와 같은 문서 골격으로 감싼 것
- **분리본:** `npm run dev`로 연 프로젝트 폴더
- **`dist`:** `npm run build` 결과를 `npm run preview`로 연 것
- **단일:** `dist-single/`

브라우저는 Playwright의 Chromium(헤드리스)을 썼고, 모두 로컬 서버(`scripts/serve.mjs`)로 열었습니다.
무작위 게임이므로 **테스트에서만** `Math.random`과 `Date`를 고정했습니다. 원본을 같은 조건으로 두 번 돌려 결과가 완전히 같은 것을 먼저 확인한 뒤 비교했습니다. 제품 코드에는 테스트용 장치를 넣지 않았습니다.

## 5. `file://` (서버 없이 더블클릭)

- 분리본·단일·원본 모두 게임이 돌아가고 상태도 같습니다.
- 음악은 세 판 모두 브라우저 보안(CORS)으로 막혀 합성 음악으로 대체됩니다. 원본도 같은 기존 동작입니다.
- 분리본은 그림이 별도 파일이라, `file://`에서는 「커리어 1면 이미지 저장」(캔버스 → PNG)이 브라우저 보안에 막힐 수 있습니다. 원본·단일은 그림이 내장돼 있어 괜찮습니다. **서버로 열면 같습니다.** 이 경우는 화면 캡처로 확인하지 않았습니다.

## 다시 점검하며 찾아 고친 것 (2차)

분리 결과를 다시 살펴보다 **빌드 도구** 쪽 버그 2개를 찾아 고쳤습니다. 게임 코드는 원래 원본과 같았습니다.

1. **폴더 경로에 한글이나 공백이 있으면 `npm run build`·`npm run check`가 실패**했습니다(예: `문서\바이라인 프로젝트`). 경로를 URL 그대로 읽은 탓입니다. 지금은 한글·공백 경로에서 빌드와 검사가 모두 통과하는 것을 확인했습니다.
2. **Windows 줄바꿈(CRLF)으로 바뀐 `index.html`에서 단일 빌드가 script 목록을 못 찾았습니다.** Git이 Windows에서 줄바꿈을 바꿔 받는 경우가 있습니다. 이제 두 줄바꿈 모두 읽고, `.gitattributes`로 저장소 안의 줄바꿈을 LF로 고정했습니다. 그림·글꼴·음악은 바이너리로 지정했습니다.
- 대소문자만 다른 파일 이름은 없습니다(Windows·macOS에서 겹칠 걱정 없음).

## 게임 수정 (총무국) — 원본 1.6에도 있던 버그

플레이 피드백으로 받은 「총무국에서 이것저것 하다 보면 값이 이상해진다」는 분리와는 상관없는, 원본에도 있던 문제였습니다. 1.6 업데이트 모듈 `src/compat/v50.js`로 고쳤습니다(기존 업데이트 방식과 같음).

- 사내 교육·복리후생·포상·임금 인상을 거듭하면 편집국 전원의 실력이 최고치(92)에 붙었고, 그 뒤엔 깎여도 화면에 92 그대로였습니다. 이제 이미 잘하는 기자일수록 덜 오르고, 예전 저장에 보이지 않게 쌓인 몫은 불러올 때 정리합니다.
- 복리후생·세분형 직급의 매달 비용이 재무 손익에서 빠져 회사 자금과 맞지 않았습니다. 이제 손익(비용)에 들어갑니다.
- 「자재 구매 계약」과 「원가 관리」가 서로 덮어써, 순서에 따라 할인이 오히려 줄었습니다. 이제 더해집니다(최대 10%).
- 재무 탭에 「지난달 자금 흐름」(손익 · 그 밖의 수지 · 자금 변화)을 추가했습니다. 판매 전략·임금 조정처럼 월 결산 밖에서 오가는 돈도 보여, 손익과 자금 변화가 맞아떨어집니다.

수정 뒤 원본(총무국 수정이 들어간 1.6)에서 같은 도구로 다시 분리했고, 이 문서의 1~4절 검증을 처음부터 다시 돌려 모두 같게 나왔습니다. 문장 2,577개, 파일 92개, 실행 비교 6가지, 저장 3가지, 시작 흐름 5가지, 스토리 5편, 화면·탭을 모두 확인했습니다.

## 확인하지 못한 것

- **Vite**: 이 작업 환경은 npm 저장소 접속이 막혀 설치할 수 없었습니다. 그래서 Vite 대신 외부 패키지가 필요 없는 Node 스크립트로 `dev`·`build`·`preview`를 만들었고, 이 명령들은 모두 실제로 실행해 확인했습니다.
- **Vercel 실제 배포**: `vercel.json`에 `buildCommand`·`outputDirectory`를 추가했지만 실제 Vercel에 올려 보지는 못했습니다. `api/presence.js`(접속자 카운터)도 실행해 보지 못했습니다. 코드는 기존 그대로입니다.
- **다른 브라우저·실기기**: Chromium 헤드리스만 썼습니다. iOS Safari, 안드로이드, Firefox는 확인하지 않았습니다.
- **소리**: 음악 파일 요청·응답까지만 확인했고, 실제로 들리는지는 확인하지 않았습니다.
- **장기 플레이**: 비교는 최대 26개월(18개월 + 이어서 8개월)까지입니다. 10년짜리 장기 플레이는 원본에서만 따로 돌렸고 분리본으로는 다시 돌리지 않았습니다.
- **내보내기 파일 다운로드 버튼**(`.txt` 저장): 코드 문자열 내보내기·가져오기만 확인했습니다.
- **구글 폰트**: 외부 인터넷이 막혀 확인하지 못했습니다. 경로는 원본과 같습니다.

## 따로 알려 드릴 점 (고치지 않음)

1. (정리함) `bribeEvent`·`bribeOut`의 실행되지 않던 옛 판은 지웠습니다. 쓰이는 새 판은 `r15-goals-favor.js`에 있습니다.
2. 음악 경로를 `assets/audio/`로 옮겼으므로, 예전 배포에 `index.html` 파일 하나만 바꿔 넣는 방식이라면 `bgm/` 폴더 대신 `assets/audio/` 폴더도 같이 올려야 합니다.
3. 그림이 파일로 나뉘어, 처음 접속할 때 그림이 내장돼 있던 원본보다 조금 늦게 뜰 수 있습니다. 로컬 서버에서는 차이를 확인하지 못했습니다.
