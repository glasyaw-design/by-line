## 왜 이렇게 나눴나 (실행 순서 보존)

원본은 script **한 개**라서 함수 선언이 맨 앞으로 끌어올려졌습니다(hoisting). 파일을 나누면 각 파일은 자기 차례에만 함수를 만들기 때문에, 앞 파일이 뒤 파일의 함수를 **바로 실행하거나 감싸면** 결과가 달라집니다.
그래서 최상위 문장마다 "읽히는 순간 실행되는 코드"가 어떤 이름을 쓰는지(호출되는 함수의 몸통까지 따라가며) 계산했고, 그 결과는 다음과 같습니다.

- 실행되는 문장(함수 선언이 아닌 것)은 **원본 순서 그대로** 파일 경계만 넣었다 — 2,560개 문장의 순서·내용이 원본과 같다 (`docs/VERIFICATION.md`)
- 순서 제약을 만드는 이름은 5개뿐이었다. 함수 선언은 원래 끌어올려지므로 **선언 위치만 앞 파일로 옮기면** 원본과 같다

| 함수 | 원본 위치 | 먼저 쓰는 곳 | 옮긴 곳 |
|---|---|---|---|
| `jo2` (조사 처리) | 바탕 `desking.js` 구획 | `articles.js`의 데이터 준비가 바로 호출 | `src/core/utils.js` |
| `eraGen` | 꼬리 `era-front.js` | 모듈 `v15.js`가 감쌈 | `src/compat/_hoisted.js` |
| `eraBox` | 꼬리 `era-front.js` | 모듈 `v18.js`가 감쌈 | `src/compat/_hoisted.js` |
| `migrate` | 꼬리 `main.js` | 모듈 `v49.js`가 감쌈 | `src/compat/_hoisted.js` |
| `deptsFor` | `base-data.js` 안 | 같은 파일 안 | (안 옮김) |

원래 자리에는 `/* [옮김] … */` 주석을 남겼습니다.

- **같은 이름이 두 번 선언된 함수** `bribeEvent`·`bribeOut`: 바탕(`actions.js`·`npc.js`)의 옛 봉투 이벤트와 1.6 개편(`v43.js`). 원본에선 끌어올림 때문에 처음부터 v43 판이 쓰였고, 분리본에선 v43.js가 읽힐 때 덮어씁니다. 그 사이에 이 함수를 쓰는 코드가 없어서(계산으로 확인) 게임 시작 시점의 결과는 같습니다. 옛 판은 쓰이지 않는 코드라 나중에 정리해도 됩니다 — 이번엔 손대지 않았습니다.

### 바탕 게임은 왜 기능별, 모듈은 왜 버전별인가

바탕 게임은 원본의 구획 주석을 경계로 큰 기능 단위 파일(core·data·systems·ui)로 나눴습니다. 경계는 순서 제약 계산에서 안전한 곳만 골랐습니다.
1.x 모듈은 앞 코드를 감싸고 덮어쓰는 **순서 자체가 의미**라서 기능별로 다시 묶지 않고 원본 순서대로 `src/compat/`에 버전별 파일로 두었습니다(원본 소스의 `v13a.js`~`v49.js`와 1:1).
나중에 기능별로 합치고 싶다면 한 모듈씩, 래퍼 순서를 지키면서 옮겨야 합니다.

| 종류 | 개수 | 어디서 | 지금 위치 |
|---|---|---|---|
| 그림 (webp) | 728 | JS `IMG` 사전 (`"키": "data:…"`) | `assets/images/키.webp` |
| 그림 (webp) | 8 | JS `RANK_IMG` 배열 (직급 그림) | `assets/images/rank_0~7.webp` |
| 그림 (webp) | 3 | CSS (로딩 화면 배경·로고) | `assets/images/loader-*.webp` |
| 글꼴 (woff) | 2 | JS가 만드는 `@font-face` (메이플스토리체 400·700) | `assets/fonts/maplestory-400·700.woff` |
| 음악 (mp3) | 8 | 원래 외부 `bgm/` 폴더 | `assets/audio/bgm_*.mp3` |

- 바이너리는 재압축 없이 그대로 꺼냈고(base64 → 바이트, 다시 base64로 되돌려 원본 문자열과 같은지 확인), 해시는 `tools/assets-manifest.json`에 있습니다.
- 같은 키의 그림이 뒤 모듈에서 다른 그림으로 다시 등록되는 경우가 37개 있습니다(리마스터). 원본처럼 뒤 것이 이기도록 `키__2.webp`처럼 따로 저장했습니다.
- 음악은 원본 HTML 안에 없던 외부 파일이라, 작업 폴더의 `bgm/` 8곡을 그대로 복사했습니다. 실제 배포 중인 `bgm/`과 다르다면 같은 이름으로 바꿔 넣으면 됩니다.
- 코드에서 바뀐 글자는 그림·글꼴 경로와 음악 경로 한 곳(`src/compat/v31.js`의 `bfStart`: `'bgm/bgm_'` → `'assets/audio/bgm_'`)뿐입니다.

## 빌드 도구

`scripts/` (Node 기본 모듈만 사용)
- `serve.mjs` 정적 서버 (mp3 Range 요청 지원)
- `build.mjs` `dist/` 복사 + `dist-single/` 합치기 (그림·글꼴을 다시 data URI로, CSS·JS를 원래 자리에)
- `check.mjs` 문법(`node --check`)·참조·해시 검사

Vite 같은 번들러는 쓰지 않았습니다. 게임 코드가 전역 이름을 공유하는 일반 script라서 묶을 필요가 없고, 이 작업 환경에선 npm 패키지를 받을 수 없어 Vite 명령을 실제로 검증할 수 없었기 때문입니다. 위 명령들은 모두 실제로 실행해 확인했습니다.

`tools/refactor/`에는 이번 분리에 쓴 스크립트(`split.mjs`, 끌어올림 분석 `vhoist.mjs`, 원본 대비 비교 `vstatic.mjs`, 브라우저 비교 `*.py`)를 참고용으로 넣었습니다. 경로가 작업 환경에 맞춰져 있어 그대로 돌리려면 경로를 고쳐야 합니다.
